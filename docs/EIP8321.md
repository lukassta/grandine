# EIP-8321 consensus implementation

Target: ethereum/consensus-specs
[12c8b24bc09b12f62688d439ba20ef00b1fdfe1f](https://github.com/ethereum/consensus-specs/tree/12c8b24bc09b12f62688d439ba20ef00b1fdfe1f/specs/_features/eip8321).
This version explicitly builds on Heze, including FOCIL, EIP-8015 and EIP-8365.

Do not mix these vectors with the mutable EIP web page. The pinned spec uses
domain 0x11000000 and progressive lists for commitments, pending commitments
and registrations. The state has progressive width 48 with gaps 8,9,10,28;
the block body has width 15 with gaps 1,6. Heze's SSZ schema remains unchanged.

## Code map

- types/src/eip8321: distinct state and block types, sharing unchanged Heze bids.
- helper_functions/src/fork.rs: Heze-to-EIP8321 upgrade, zero commitments and empty queue.
- transition_functions/src/eip8321: registration, RANDAO, activation and typed transition.
- transition_functions/src/combined.rs: real EIP8321 dispatch, stopping at fork boundaries.
- transition_functions/src/electra/block_processing.rs: shared new-validator helper
  appends a zero commitment only in EIP8321 states; top-ups preserve commitments.
- helper_functions/src/signing.rs: fork-independent genesis-bound registrations;
  voluntary exits retain the inherited Capella domain in Heze and EIP8321.
- Genesis and serialization recognize the distinct phase. The small networking patch
  extends the upstream Heze dependency with the new phase and decodes EIP8321 blocks
  with their own schema. Unchanged inherited messages retain their existing formats.

Registrations are one-time, capped at 128 per block and reject pending duplicates.
They activate at the transition into inclusion epoch + 3, immediately after registry
updates. Registered proposers reveal a nonzero BLAKE3-chain preimage, use the G2
infinity BLS signature and mix BLAKE3(old mix || reveal). Unregistered proposers
use the existing BLS/SHA256/XOR path and must have a zero hash-chain reveal.
Hash-chain checks remain mandatory when BLS checks are disabled.

## Run in Ubuntu

    bash scripts/prepare_eip8321_dependencies.sh
    make test-eip8321
    bash scripts/test_eip8321.sh minimal
    bash scripts/test_eip8321.sh mainnet
    make test-heze

The script checks SHA-256 and extracts the committed archive; it does not regenerate
Python tests. After compilation, execution takes seconds.
EIP8321_VECTORS_DIR can point to another generated reference root containing
minimal/ and mainnet/.

There are 368 official cases across 16 groups: RANDAO, registrations, pending
commitments, pending deposits, fork, slots, blocks and finality for both presets.
Additional Rust regressions check fork independence, genesis binding, pending
and reveal replay, one link per proposal, registration budget, same-block duplicates
and the exact fork slot. EIP8321_INVENTORY.json records exact counts. This focused suite does not
claim to execute every upstream category.

Fixtures are unchanged copies of generated official vectors. Complete blocks
and slots use production combined dispatch. Valid cases compare full post-state
roots, negative cases must fail processing. Input SSZ errors and panics fail the
harness, including for negative cases. Per-case TSV files go to test-vectors/reports.

The upstream mainnet lifecycle generator in this revision asserts 256 <= 128
before producing a case. That missing case is not claimed as passed or patched.
The official minimal lifecycle case is included and passes.

Regenerate in the pinned consensus-specs checkout:

    make test reftests=true fork=eip8321

The known mainnet generator failure remains. For a successful minimal-only run:

    make test reftests=true fork=eip8321 preset=minimal

Package the selected categories:

    python3 scripts/package_eip8321_vectors.py /path/to/consensus-specs

## GitHub Actions and scope

The EIP-8321 consensus vectors workflow executes the pinned vectors, additional
signature regression and Heze/Gloas regressions, uploading per-case reports.
General CI also extracts the archive before compiling/running integration tests.

This implements the consensus state transition. Validator chain-secret storage,
registration gossip/pools, proposal production and Kurtosis interoperability
remain client work. Passing the focused workflow does not establish live interop.

## Upstream Heze base

The base is Subhasish-Behera/grandine Subh/heze2 at
c92f155458c12c08207ccb56f29ecbb6b6f952b7, retaining its FOCIL integration.
The preceding commit adds EIP-8015 and EIP-8365 for the pinned teacher vectors.
This is not heze-devnet-3 / EIP-8198.

The official self-slashing block vectors also exposed missing cancellation of
pending builder payments in the upstream base. The post-Gloas slashing wrapper
now removes payments owned by the slashed proposer for both slashing paths.
The earlier Electra behavior stays separate.

## Port validation

On this base, the dedicated runner passed all 368 archived cases (192 minimal,
176 mainnet), four additional RANDAO regressions and the EIP8321 genesis test.
The Heze runner also passed its 44 official cases, six Gloas comparisons and
schema/genesis checks. The release workspace cargo check succeeds.

The network shim applies cleanly to the pinned submodule and is idempotent.
It is stored as a patch rather than changing the submodule gitlink; a modified
eth2_libp2p working directory after preparation is therefore expected.
